# Milestone: V14 Adaptive Orchestration

## Status

Active on `codex/v14-adaptive-orchestration`.

## Goal

Turn one software goal into an optimized, native IDE specialist run: deterministic
least-sufficient runtime routing, dependency-safe execution, verified fan-in, visible decisions,
independent review, and durable memory.

## Shipped

- V14 product goal, feature package, test plan, and proposed architecture boundary.
- Current cross-host research covering Codex, Copilot/VS Code, Claude Code, AutoGen, and scheduler
  feasibility/scoring practice.

Implementation and dogfood are not yet shipped.

## Why It Matters

V13 proved correctness but required too much manual host ceremony and used manually selected
high-effort runtimes. V14 is the layer that makes the system practical to invoke from an ordinary
IDE conversation while preserving the evidence chain.

  confirmed extension hook.
- The controller must remain small enough to avoid repeating the deferred universal scheduler.

## User-Facing Overview

V14 is in architecture. Its release target is the usable orchestration product: one request becomes
task-shaped specialists, least-sufficient runtime assignments, native parallel IDE work, verified
integration, and a concise live trace. No release claim is made until all three dogfood scales and
independent reviews pass.
