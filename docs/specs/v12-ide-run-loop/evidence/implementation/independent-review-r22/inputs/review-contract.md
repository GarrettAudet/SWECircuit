# Revision 22 Independent Review Contract

## Purpose

Independently determine whether the exact Revision 22 implementation closes the Revision 21 provenance failure and the npm 11 closed-environment defect without introducing a new trust, cleanup, reconstruction, or test-quality bypass.

Producer tests and the verified producer handoff are authenticated evidence, not this review's semantic verdict. Review only the immutable snapshots declared by the package.

## Required Review

1. Authenticate the complete review package and every declared snapshot before semantic use. Reconstruct and verify the exact Revision 22 producer package from its declared context sources.
2. Confirm the production parent creates two distinct, operation-contained, plain, empty, one-link npm configuration files and never restores, resolves, or accepts host npm configuration.
3. Confirm both npm configuration paths and identities are checked before every relevant spawn, including containment outside repository, candidate, and cache; reject missing, aliased, substituted, linked, non-empty, out-of-root, or case-insensitively colliding paths before child execution.
4. Confirm disposable paths remain invocation evidence and do not enter stable reconstruction, while stable policy and empty-file identities remain digest-bound.
5. Confirm receipts and child evidence are derived from actual runtime enforcement rather than accepted as static claims.
6. Confirm the child harness independently validates the exact private configuration contract before importing candidate runtime code.
7. Confirm the Revision 21 compatibility adapter and host-configuration fallback are absent, and installed npm 11 succeeds through the unmodified production environment.
8. Confirm the focused tests reject the old same-path `NUL` or `/dev/null` configuration and all substitution, alias, hard-link, non-empty, missing, and host-injection cases.
9. Confirm outside-repository proof and path containment are platform-neutral and do not rely on Windows-only path spelling.
10. Confirm success, failure, interruption, and promotion paths remove private operation roots and cannot promote output before receipt-last evidence.
11. Confirm the real copied-production lifecycle executes actual compile, approve, verify, package-bound fan-in, raw comparison, canonical gate, and all ten negative routes rather than projecting synthetic results.
12. Confirm every final source and producer artifact is reconstructable from preserved immutable inputs; specifically recheck the Revision 21 unpreserved-working-tree failure cannot recur.
13. Confirm the five-file implementation scope is exact and protected package metadata, lockfile, canonical gate, verifier, prior evidence, and package inputs retain their authenticated identities.
14. Search for new circularity, confused-deputy, replay, substitution, stale-output, path, process, promotion, cleanup, provenance, or test-quality defects.

## Verdict

Return `pass` only if every required review point is satisfied and no release-blocking finding remains. Return `fix`, `diagnose`, `redesign`, or `block` with exact source and evidence references for any defect. Remain read-only and do not claim release readiness, hosted CI, owner approval, or merge authority.
